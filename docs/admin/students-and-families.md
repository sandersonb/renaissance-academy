# Students & families

Almost everything about an individual student happens on their **family page**.

## Finding a family

- **Search** menu → type part of a student's first or last name → **Search**.
- Or from the **Dashboard**, click any count (or a grade heading) to get a filtered
  list, then click the family.

Search results are grouped by family. Click the parent's name to open the family
page.

## The family page

At the top is the **parent/guardian** record; below it, each **student**; at the
bottom, **notes**.

### Editing the parent

Select **Edit** on the parent card to change contact details (name, email, phones,
address, relationship). Save writes the change and records a note automatically.

### Each student

For every student you can see their grade, date of birth, status, waitlist
position (if any), any deadline, and their survey answers. You can:

- **Edit** — correct the name, gender, grade, or date of birth.
- **Delete** — permanently remove the student record (asks you to confirm).
- **Change status** — see below.

To add a student to this family, use **Add student** at the top of the Students
section.

### Changing a student's status

Each student has a **Change status** dropdown that only lists the *valid next
steps* from where they are now (for example, an offered student can be moved toward
paperwork). Pick one and select **Apply**. The system also handles the ripple
effects for you (for instance, promoting the next person off the waitlist when a
seat frees up) and logs a note.

**Force status (advanced).** Occasionally you need to set a status the normal flow
won't allow — a manual correction. Use **Force status…**, choose the status, and
confirm. This skips the usual rules and side-effects, so use it only for genuine
cleanup. It's always recorded as a note so there's a clear trail.

### Notes

Notes are a running history for the family — call logs, reminders, and an automatic
record of every change made in the portal. Add your own with the box at the bottom.
Notes are kept (not deleted) so the office always has context.

## Common tasks, step by step

**Extend a specific offer manually**
1. Open the family → find the student.
2. Change status toward *Offer* / *Offer Pending* as appropriate → **Apply**.
   (Most offers go out automatically via the lottery and the Notifications tools —
   see [Settings & staff accounts](settings-and-admins.md).)

**Record that a family declined**
1. Open the family → the student → **Change status** → the decline option → **Apply**.

**Fix a returning student's details before re-enrollment**
- If they're already an applicant, edit them here. If it's the *current-student
  roster* that's wrong (name/DOB used to match returning families), fix it on the
  **[Roster](lottery-and-year.md)** page instead.
